# Publisher 6.0.0 — штатное планирование Quarto

Новый публичный вход: `subprojects: [{path: theory, to: default}]`. Строки прежних версий не поддерживаются. `to` принимает только `default`, `html`, `revealjs`; путь исходников и порядок монтирования прежние.

Убран предварительный план форматов из N вызовов `inspect` документов и запасной путь из N вызовов `render`. Каждый дочерний проект выполняет одну штатную команду Quarto для всего проекта, сохраняя книгу или сайт, метаданные, профили и обработчики. `default` выбирает первый штатный формат; для HTML при PDF первым следует задать `to: html`. Формат не выводится из результата `inspect` проекта.

Независимые списки выбранных Quarto исходников корня и дочерних проектов проверяются до очистки результатов. Фактический каталог Core сравнивается с ними и текущими HTML-результатами внутри существующей операции, до ZIP соответствующего владельца; явный `to` сверяется с фактическим форматом. Режимы без Core и частичная сборка не получают новой модельной гарантии. Живые stdout/stderr и сообщения о начале и завершении рендера и финализации позволяют видеть текущий этап.

Это кандидат. Аудит вызовов `inspect` всех расширений принят отдельно; адресные штатные проверки, сравнительный замер, независимая рецензия, CI точного исходника, неизменяемая публикация и установка проверяются отдельно. Полные сборки Java/SP, все 135 экспортов и C/P не объявляются проверенными этим изменением. Текущие конфигурации Java/SP меняет только Root после принятия опубликованных расширений.
