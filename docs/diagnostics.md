# Диагностика Publisher (course-site)

Справочник описывает ошибки владельца составной сборки. Структура сообщения:
`[ID] course-site: русский смысл (источник; ID объекта; поле; связано; подсказка)`.
Контекст появляется только там, где он известен. Источник — входной проект или
документ, а не выдуманная строка QMD. Путь текущего результата, временной коллекции
или модуля отмечается как связанный путь; номер строки готового HTML не является
строкой исходного документа. Сообщение не вводит сериализованный отчёт.

| ID | Когда возникает | Доступный контекст | Действие автора |
| --- | --- | --- | --- |
| `SITE.CONFIG_INVALID` | Неверный тип корня, прежняя конфигурация, пустой список компонентов, некорректные профили, отсутствие output-dir или несогласованная аудитория | Проект, компонент/курс, `project.type`, `subprojects`, `course-site`, `QUARTO_PROFILE`, `project.output-dir` или `course.view` | Используйте native website, непустой список папок, уникальные профили, самостоятельный output-dir и согласованную аудиторию. |
| `SITE.SUBPROJECT_INVALID` | Абсолютный/выходящий путь, символическая ссылка, повторяющиеся или вложенные компоненты, источник не является файлом | Проект, `subprojects`, `input` или `path`, связанные пути и компонент | Выберите обычные файлы и непересекающиеся папки внутри проекта. |
| `SITE.OUTPUT_OVERLAP` | Каталоги результата пересекаются с источниками, служебными данными, другими outputs, аудиториями или корневым монтированием; очистка затронет исходник/кеш | Проект, компонент, `project.output-dir` или `subprojects`, конфликтующие пути | Разделите каталоги результатов и исходники; перенесите исходные файлы из output. |
| `SITE.FORMAT_AMBIGUOUS` | Несколько веб-форматов одного документа либо не выбран единственный невеб-формат | Входной документ, проект, `format` | Выберите один веб-формат или используйте профиль формата. HTML вместе с PDF допустим. |
| `SITE.COLLECTION_INVALID` | Нет списка результатов/каталога, повторяются outputs, текущая коллекция не согласована с компонентом/профилями, коллекция повреждена | Проект, компонент, коллекция/каталог, поля окружения или коллекции | Установите collect последним post-render hook; проверьте native output-dir и повторите сборку. |
| `SITE.CURRENT_RESULT_MISSING` | Отсутствует коллекция, текущий файл Quarto, собранный файл или результат Core | Проект, компонент, `collection`, `files`, `nativeOutputs` или `outputFiles`, путь результата | Проверьте hooks производителя и повторите успешную сборку; старые файлы не заменяют текущий результат. |
| `SITE.SIBLING_MISSING` | Требуемый файл соседнего Core/QRC не установлен | Модуль, имя расширения, `module` | Установите совместимые Core/QRC рядом с course-site в том же namespace. Ошибка исполнения уже установленного модуля сохраняет исходную причину и ID владельца. |

## Внешняя команда и граница hook

Собственный обычный Error имеет `name: ExtensionDiagnostic` и `code`.
Внешний отказ имеет `name: ExternalToolFailure`, `tool: quarto`, `exitCode`,
`stdout`, `stderr`, `forwarded` и `cause`. Для неудачного запуска `exitCode`
равен null, а исходная ошибка запуска сохранена в cause. Publisher не разбирает
stderr и не присваивает ему смысловой SITE ID. Trace сохраняет прежние
`args`, `cwd`, `elapsedMs`, `exitCode`.

Узкая граница pre/post/collect печатает ожидаемую ошибку и завершает hook
с ненулевым кодом. Уже переданные child stdout/stderr не печатаются повторно.
Неизвестные исключения пробрасываются со stack. Прежние записи не подтверждают
новый результат; отказ после collect также прекращает composition.

## Предупреждения самостоятельного проекта

`fail-if-warnings: true` задаётся native конфигурацией каждого публичного проекта
или общим `metadata-files`, подключённым каждым проектом. Корневой CLI-флаг
не обещает общей политики всех запускаемых scripts. У Publisher нет собственного
warning option, пересылки CLI-флагов или распознавания предупреждений регулярным
выражением. Core отдельно задаёт свою политику JSON-экспорта.

## Проверка синхронности

ID и контекст проверяют `site-paths`, `site-source-paths`, `site-collection`,
`site-effective-formats` и `site-siblings`; потоки и stack — `site-process`;
текущую установленную composition и строгость предупреждений — `site-native`
и `site-native warnings`. `site-domains` проверяет опциональные установленные
Core/QRC. Недопустимые примеры остаются отрицательными fixtures в tests;
готовая демонстрация содержит только успешные документы.
