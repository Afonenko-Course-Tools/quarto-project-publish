# Контракт публикации 1.2

## Идентичность

Цель задаётся парой `(namespace, id)`. Namespace определяет проект-производитель. ID берётся из Quarto и уникален во всех выбранных документах этого пространства имён. Например, `book:fig-demo` и `lectures:fig-demo` различаются; два `lectures:sec-intro` в разных файлах считаются ошибкой. Для повторяющихся слайдов «Итоги» используйте `sec-l01-summary`, `sec-l02-summary`.

Внутри производителя используются обычные ссылки Quarto. Межпроектные ссылки записываются как `@namespace:kind-id` или `xref namespace kind-id [text] [style=number]`. Перечень стандартных типов: `fig`, `tbl`, `lst`, `eq`, `sec`, `thm`, `lem`, `cor`, `prp`, `cnj`, `def`, `exm`, `exr`, `sol`, `rem`, `alg`, `nte`, `tip`, `wrn`, `imp`, `cau`. Пользовательские типы читаются из `crossref.custom`. Это каталог crossref, а не любых HTML-ID.

Группы именованных ссылок сохраняют порядок, префиксы и суффиксы Pandoc; разделитель — точка с запятой. Библиографические ссылки и ссылки каталога должны находиться в разных группах Cite. DOI и библиографические ключи не получают автоматического доступа к каталогу. Запись `namespace:kind-id` зарезервирована для каталога.

## Обязательные проверки

| Проверка | Поведение |
|---|---|
| Проект отсутствует или формат неизвестен | Ошибка до рендера |
| Пересечение output и исходников | Ошибка до копирования |
| Штатная пробная ссылка не разрешилась | Ошибка, подпись не вычисляется вручную |
| ID повторён в namespace | Ошибка с обеими страницами |
| HTML-якорь отсутствует или повторён | Ошибка |
| Неизвестная цель или namespace в ссылке | Ошибка с исходной страницей |
| Объект Revealjs не принадлежит слайду с ID | Ошибка |
| Удалённая цель есть только в старом каталоге | Старый каталог не участвует в сборке |

Наличие каталога предыдущей сборки не является условием запуска. Изменение output-file или порядка глав обновляет URL и подписи при следующей сборке. Подписи берутся из контекста производителя: язык и стиль потребителя их не переопределяют.

## Публичный экспорт

`reference-catalog.exports` — необязательное отображение локального namespace в `"*"` или список явных ID:

```yaml
reference-catalog:
  publication: {title: Операционные системы}
  exports:
    book: [sec-memory, sec-processes]
    lectures: "*"
```

Отсутствие `exports` означает все собственные цели; `{}` — ни одной. Указание namespace импорта, неизвестного локального проекта, повторного ID в списке или отсутствующей цели отклоняется. Нельзя экспортировать ID, скрытый текущим профилем: при необходимости профиль переопределяет список экспорта. Выбор публичных целей не уменьшает область разрешения внутренних ссылок и не скрывает страницы, поисковые записи или содержимое HTML.

Импортированные цели используются только при связывании и никогда не записываются в новый каталог. `publication.title` — необязательное человекочитаемое название всей публикации; оно не заменяет namespace и не привязывает расширение к учебным ролям.

## Источники внешних каталогов

```yaml
reference-catalog:
  imports:
    os:
      source: https://example.edu/catalogs/os.json
      namespace: book
      base-url: https://example.edu/os/
      title: Операционные системы
      style: external
```

`source` — непустой HTTP(S) URL, `file:` URL или локальный путь. Название JSON-файла не фиксировано. Относительные пути разрешаются от корня составного проекта; разрешены абсолютные пути и соседние каталоги. `file` поддерживается как прежнее имя настройки локального файла; ровно одно из `file` и `source` обязательно.

`namespace` выбирает пространство производителя, ключ `os` задаёт псевдоним потребителя. `base-url` обязателен, указывает корень целевого сайта, заканчивается `/` и не содержит query/fragment. Он не выводится из адреса JSON. Для совместимости у реэкспортированной цели старой схемы `/2` сохраняется её собственный проверенный `baseUrl`; у обычных целей используется адрес из конфигурации. Новая схема `/3` запрещает внешние адреса и настройки потребителя внутри целей. Изменение источника на локальную копию само по себе не переключает ссылки на localhost.

Все импорты загружаются и проверяются до запуска дочерних рендеров. Уникальный источник читается один раз, даже если из него импортировано несколько namespace; полученные цели сохраняются в состоянии конкретной сборки. HTTP(S) поддерживает перенаправления, ошибочные ответы и некорректные данные прерывают сборку. Скрытого возврата к прежнему каталогу нет. Между сборками постоянный кеш и lock-файл не используются; для автономной работы нужен локальный снимок. Проверка доступности целевых страниц и их якорей по сети не выполняется.

Preview получает свежие внешние каталоги при перестроении текущего проекта. Изменения на HTTP-сервере и в локальных файлах за пределами корня сами по себе перестроение не запускают.

## Подписи внешних ссылок

`imports.<alias>.style` задаёт стиль обычного `@alias:id`; значения: `default`, `number`, `title`, `external`. Без настройки сохраняется `default`. Shortcode позволяет выбрать `style="title"`, `style="external"` или `style="number"` для отдельной ссылки. `default` наследует настройку импорта; явно заданный другой стиль её переопределяет.

- `default`: штатная подпись производителя, например «Глава 2».
- `number`: штатный номер; отсутствие номера — ошибка, если автор не задал собственный текст.
- `title`: название заголовка без номера; для других объектов и старых каталогов без `title` используется штатная подпись.
- `external`: название либо авторский текст, затем название публикации и декоративный маркер ↗. Применяется только к импортированной цели.

Название публикации выбирается в порядке `imports.<alias>.title`, `catalog.publication.title`, псевдоним импорта. Названия и имена публикаций — обычный текст, экранируемый при записи HTML. Авторский текст shortcode сохраняется; для `external` к нему добавляется источник. Все импортированные ссылки получают `rel="external"`, без обязательного `target="_blank"`. Встроенный CSS добавляется только на страницы с внешним стилем и использует классы `qrc-external`, `qrc-title`, `qrc-source`, `qrc-external-marker`.

`[-@alias:id]` сохраняет явный запрос номера независимо от настроек импорта. Для ненумерованной цели используйте название или свой текст.

## Формат каталога

Экспорт имеет `schema: quarto-reference-catalog/3`, происхождение в `generator`, необязательное `publication.title` и словарь `targets`. Цель содержит namespace, ID, относительный путь HTML, fragment, необязательный slide, штатные подписи HTML/текст и необязательное текстовое `title` заголовка. Адрес внешней публикации и настройки потребителя не экспортируются.

JSON Schema текущего экспорта: `schemas/catalog.schema.json`; прежняя схема сохранена как `schemas/catalog-v2.schema.json`. Импорт принимает `/2` и `/3`; старым целям без `title` не приписывается искусственное название. Потребитель 1.1 не читает `/3`: сначала обновите расширение у потребителя. Внешний каталог остаётся доверенным артефактом издателя: штатные HTML-подписи не санитизируются как произвольный пользовательский ввод.

Взаимные ссылки независимых публикаций работают через подготовленные снимки, без вызова сборки другого проекта. Для первоначального запуска сначала сформируйте каталоги собственных целей, затем добавляйте взаимные импорты. Отдельный режим экспорта до разрешения внешних ссылок в этой версии не вводится.

## Размещение

`home` — namespace одного HTML-проекта, публикуемого в корне. В этом режиме корневой `project.render` равен `[]`, у выбранного проекта отсутствует `mount`, а его результат содержит `index.html`. Если `home` не указан, корневые документы образуют самостоятельный портал. `mount` остальных проектов — уникальное имя непосредственного подкаталога сайта.

## Профили

Активный список профилей Quarto — вход координатора. Он явно передаётся в inspect и render; очередность сохраняется. Каждый производитель обязан иметь `_quarto-<profile>.yml` для каждого выбранного профиля. Отсутствующий файл считается ошибкой до сборки. Профили без активного выбора не навязываются: старые проекты без профилей сохраняют поведение. Preview повторяет выбранный список при каждом изменении исходников. Каталог и поиск вычисляются заново только из готового результата выбранного профиля; удалённые цели не восстанавливаются из предыдущей сборки.

Бинарные ресурсы, сформированные post-render подпроекта, например `_downloads/*.zip`, переносятся вместе с его output. Разрешение скачивания и состав архива определяет расширение производителя; координатор не архивирует дерево исходников.

Директории результатов, объявленные корневым проектом и его `_quarto-*.yml`, исключаются из снимка исходников и наблюдения preview. Это предотвращает копирование предыдущей полной публикации во временное дерево студенческой сборки.
