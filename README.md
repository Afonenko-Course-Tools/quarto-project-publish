# Quarto Reference Catalog

Перекрёстные ссылки между HTML-книгой и наборами Revealjs-слайдов. Книга, лекции и практика собираются самостоятельными проектами и публикуются одним статическим сайтом. Подписи и номера формирует Quarto. Расширение связывает готовые документы, поэтому взаимные ссылки работают уже при первой сборке.

Требуется **Quarto ≥ 1.10**. Точный выпуск и верхняя граница не закреплены. TypeScript/Deno и Lua/Pandoc входят в Quarto; HTML-парсер поставляется в расширении. Python, Node.js, npm и CUE не требуются.

Рабочий каталог должен находиться в пути без пробелов: это ограничение разбора проектных hooks в Quarto 1.10/1.11. Кириллица допустима.

## Установка

```sh
quarto add AfonenkoA/quarto-reference-catalog@v1.0.0
```

## Книга как главная страница

В корне курса расположен `_quarto.yml`, а в `book`, `lectures`, `practice` — самостоятельные проекты со своими `_quarto.yml`:

```yaml
project:
  type: website
  output-dir: _site
  render: []
filters: [reference-catalog]
reference-catalog:
  namespace: site
  home: book
  projects:
    book: {path: book, format: html}
    lectures: {path: lectures, format: revealjs}
    practice: {path: practice, format: revealjs}
```

`home` выбирает HTML-проект, публикуемый в корне сайта. Главная страница — настоящий `index.html` этого проекта. Книга сохраняет оглавление, поиск, навигацию и ресурсы. Отдельный внешний `index.qmd`, копия одной страницы и перенаправление не нужны. `book/index.qmd` остаётся обычной первой страницей самой книги.

Для выбранного `home` не задаётся `mount`; результат должен содержать `index.html`. `project.render: []` означает, что у корневого координатора нет собственных документов. Например, глава `book/topics/types.qmd` окажется в `_site/topics/types.html`, а лекция — в `_site/lectures/01/types.html`.

Если нужен отдельный авторский портал, удалите `home`, укажите `render: [index.qmd]` и создайте его страницу. Тогда книга будет размещена в `book/`. Для остальных проектов `mount` позволяет изменить каталог публикации; по умолчанию используется namespace. Столкновение каталога слайдов с содержимым главного проекта считается ошибкой.

## Ссылки

```qmd
@book:fig-memory
@lectures:sec-memory
@practice:exr-clamp
[-@book:eq-energy]
{{< xref lectures sec-memory "Разбор на слайдах" >}}
{{< xref book fig-memory style="number" >}}
```

Внутри проекта обычные `@fig-memory` и `@sec-types` обрабатывает Quarto. Межпроектная цель определяется парой namespace и ID. Одинаковые ID разных проектов допустимы; повторение ID в одном namespace останавливает сборку.

Поддерживаются стандартные семейства Quarto crossref, пользовательские `crossref.custom`, приложения и подрисунки. Для ненумерованных заголовков подписью служит название; запрос только номера у такой цели отклоняется. Слайдам задавайте явные устойчивые ID. Ссылка на объект Revealjs открывает содержащий его слайд и раскрывает фрагмент с объектом.

## Сборка и публикация

```sh
quarto render
quarto preview --no-browser --port 4200
```

`_site` содержит весь сайт, `.nojekyll` и `reference-catalog.json`. Внутренние ссылки относительные: они работают локально и под префиксом `OWNER.github.io/REPOSITORY/`. На GitHub Pages главной страницей будет книга, если задано `home: book`.

Preview отслеживает вложенные исходники и перестраивает общий сайт с обратными ссылками. При ошибке он продолжает отдавать последнюю успешную сборку. Запускайте команды из корня курса; на один рабочий каталог допускается один процесс сборки или preview.

Для экспорта каталога другому курсу предусмотрен `reference-catalog.imports`; формат и ограничения описаны в [контракте](docs/contract.md). Публикация поддерживает HTML и Revealjs. Генерация PDF-раздаточных материалов и платформенных заданий — отдельные задачи.

## Пример

Из корня этого репозитория:

```sh
cd examples/course
quarto add ../..
quarto render
quarto preview
```

Пример демонстрирует три направления публикации, взаимные ссылки, несколько типов целей и вложенные слайды. Общий курс с заданиями Cloud и PrairieLearn находится в [programming-course-template](https://github.com/BSU-RFCT-Afonenko-Cources/programming-course-template).

## Устройство

| Каталог в `_extensions/reference-catalog` | Ответственность |
|---|---|
| `domain` | Цели, уникальность ID, разрешение ссылок и URL |
| `application` | Сценарии сборки через порты |
| `infrastructure` | Quarto CLI, файлы, HTML, публикация и поиск |
| `lua` | AST-цели и межпроектные ссылки |
| `entrypoints` | Hooks и preview |
| `browser` | Переход к объектам Revealjs |
| `vendor` | Локальные зависимости с лицензиями |

Расширение использует публичный AST и итоговый HTML, не читает внутренний `.quarto/xref` и не вычисляет номера самостоятельно. Подробности — в [архитектуре](docs/architecture.md).

## Хранение в Git

Корневой `_extensions/reference-catalog/` — исходники расширения, их нужно коммитить. Установленная копия в `examples/course/_extensions/` восстанавливается командой `quarto add ../..` и исключена из Git вместе с результатами рендера. После изменения расширения повторите установку в пример.

В самостоятельном курсе установленный `_extensions/` следует хранить вместе с исходниками. [Quarto рассматривает расширения как исходный код проекта](https://quarto.org/docs/extensions/managing.html), обеспечивая воспроизводимость без повторной загрузки. Название владельца или репозитория используется только при установке и не влияет на сборку или ссылки.
