# Составная публикация и новый банк

Это подготовка согласованного следующего выпуска, а не обещание опубликованной версии. [Целевой контракт Core](../../quarto-course/spec/authoring-model-next.md) задаёт общую модель; [план владельца](plans/2026-10-08-implementation.md) фиксирует порядок внедрения и свежие проверки. Существующие публичные API владельца сохраняются. После реализации и проверки эти правила переносятся в действующий контракт и README. Минимум следующего выпуска — Quarto 1.11.5, CUE 0.17.1.

Publisher собирает самостоятельные native проекты, сохраняет их области Course-идентичности и передаёт Core/QRC только текущие результаты успешных процессов. Новый банк не меняет `subprojects`, размещение частей, pre/post/collect или ownership. Обычная книга без Core остаётся обычной книгой; каталог с именем `task` сам по себе не включает банк.

В части, которая объявляет канонические задачи, автор задаёт `exercise-bank: true` и политику условия в `_metadata.yml` нужной области. Страницы работ могут находиться рядом, вне этой области. В одном выбранном book-проекте сохраняется одна экспортная идентичность; вложенные самостоятельные проекты не объединяются в банк.

```yaml
# book/tasks/_metadata.yml
exercise-bank: true
exercise-statement-visibility: open
```

Каждый публичный native проект — root и все выбранные части — задаёт `lang: ru` и `fail-if-warnings: true`. Quarto использует собственную настройку ребёнка; CLI-флаг корня не наследуется child scripts. QRC получает уже размещённые HTML/Reveal outputs и их текущий поиск.

В student-результате нет restricted условий, решений обычных открытых задач, закрытых ключей и заметок преподавателя. Проверяются HTML, mounted resources, каталоги ссылок и search, а не только видимое дерево DOM. Full получает свою текущую проекцию в отдельном output. Нативное действие `repo-actions: [source]` может вести в GitHub; source modal и копирование сырых QMD с закрытыми условиями в student output не включаются.

`examples/course` остаётся самостоятельной демонстрацией Publisher/QRC без Core. Её обычные главы не нужно превращать в банк ради новой модели. Совместный сценарий с Core проверяется fixtures владельца после завершения Core.

Сейчас release pins ещё указывают на последние опубликованные теги. Новые install/demo/source refs появятся только после решения о версиях и успешных releases; новый URL до этого не выдумывается. Готовый asset должен содержать точный producer commit и фактические зависимости в `BUILD.json`. Эта подготовка не подтверждает render, CI или выпуск.
