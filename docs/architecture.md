# Архитектура

Reference Catalog связывает опубликованные документы и не интерпретирует задания, ВМ или результаты оценивания.

## Границы модулей

`domain` содержит модель целей, правила уникальности и относительные URL. Этот слой не импортирует Deno, файловую систему, Quarto или HTML-парсер. `application/workflow.ts` задаёт сценарии через интерфейс `BuildPorts`; `infrastructure/runtime.ts` соединяет их с конкретными адаптерами. Короткие входные модули подключают сценарии к обработчикам проекта Quarto.

`render.ts` отвечает за запуск Quarto, `pages.ts` — за извлечение опубликованных целей, `linker.ts` — за связывание, `publish.ts` — за итоговое дерево сайта, `search.ts` — за обновление поискового индекса. Только `html.ts` импортирует parse5. Lua-модули работают на границе AST, `browser/navigation.js` — с опубликованными HTML-узлами и публичным API Revealjs.

Браузерный адаптер общий для всех страниц: он находит существующий ID, переводит Revealjs к нужному слайду и индексу вложенного фрагмента, раскрывает предков `<details>`/Bootstrap `.collapse`. Учебные роли, классы темы, дополнительные ID и собственная модель ссылок ему не нужны. URL-параметр `qrc-target` используется только при входе на страницу; последующие переходы по слайдам не возвращают пользователя к прежней цели. Обработчик печати принадлежит представлению документа и здесь не устанавливается.

## Сборка

1. `pre-render` получает эффективную конфигурацию через `quarto inspect`, проверяет подпроекты, `home`, `mount`, экспорт и каталог вывода. Через порт `imports` загружаются и проверяются внешние каталоги; до завершения этого шага дочерние рендеры не запускаются.
2. Авторские исходники копируются в изолированную временную сборку с сохранением относительных включений и ресурсов. Каждый подпроект рендерится один раз штатным Quarto. Вложенный запуск координатора отключён переменной окружения.
3. На фазе `pre-ast` ссылки между namespace заменяются помеченными ссылками. Целевой каталог ещё не требуется.
4. На `post-ast` собираются цели и добавляются скрытые штатные ссылки-пробы. Их номера, язык, приложения и пользовательские типы обрабатывает сам Quarto.
5. `post-render` формирует дерево публикации. При наличии `home` весь результат этого проекта размещается в корне; остальные проекты — под своими mount. В режиме портала сохраняется вывод корневых документов.
6. После получения собственных целей проверяются ID, HTML-якоря и выбор экспорта. Для разрешения ссылок используется объединение всех собственных целей и снимка импортов из состояния сборки. Удаляются пробы, обновляется поиск; `reference-catalog.json` содержит только выбранные собственные цели.
7. Готовый кандидат заменяет каталог результатов. Только успешное завершение команды разрешает публикацию в CI.

Межпроектные циклы не влияют на порядок рендера. Номера не вычисляются расширением, внутренний `.quarto/xref` не читается, старый каталог не используется для исправления отсутствующих целей.

## Главный проект

`home` задаёт размещение всего проекта, а не перенаправление браузера. Каталог книги становится корнем публикации, поэтому её CSS, изображения, поиск, обычные ссылки, оглавление и навигация сохраняют относительное расположение. Каталог целей строится уже по итоговому размещению.

Корневой проект с `render: []` использует штатные hooks Quarto без собственного документа. Главный проект обязан выдавать `index.html`. Для предотвращения перезаписи контента совпадение его каталогов с mount слайдов считается ошибкой. Имена `reference-catalog.json` и `.nojekyll` зарезервированы за публикацией.

## Предпросмотр

Сервер подключён через `project.preview.serve`. Сгенерированный временный входной модуль находит установленный пакет независимо от namespace владельца. Сервер следит за исходниками, объединяет события и выполняет полные сборки последовательно. Успешный результат обновляет отдельный снимок и посылает браузеру SSE-событие; ошибка оставляет последний успешный снимок доступным.

Полная пересборка нужна для обновления обратных ссылок после перенумерации или удаления целей. Запускается один процесс сборки на рабочий каталог. Выходной каталог должен быть непосредственным подкаталогом корня, например `_site` или `docs`.

## Пути и ресурсы

Для HTML используются относительные URL, для внешних каталогов — явный HTTP(S) `base-url`. Revealjs получает hash содержащего слайда и, при необходимости, `qrc-target` для конкретного объекта. ID слайда стабилен и не зависит от его номера.

`.qrc`, `.quarto`, `.git`, `_generated`, `_site`, `_book`, `_output`, `node_modules` и `*_files` исключены из снимка авторских исходников. Ресурсы следует хранить в обычных каталогах, например `assets`. Символические ссылки не поддерживаются. Для нестандартных расширений файлов список отслеживаемых ресурсов задаётся в `entrypoints/preview.ts`.

## Публичные интерфейсы

Минимум `Quarto >= 1.10.0` выражает требуемый набор возможностей. Условия на конкретные patch-версии отсутствуют. Версия фактического Quarto записывается в каталог как происхождение результата.

Основания: [Quarto AST](https://quarto.org/docs/advanced/quarto-ast.html), [Lua API](https://quarto.org/docs/extensions/lua-api.html), [проектные скрипты](https://quarto.org/docs/projects/scripts.html), [metadata extensions](https://quarto.org/docs/extensions/metadata.html), [Revealjs links](https://revealjs.com/links/).

## Независимые источники и экспорт

`import-config.ts` нормализует источники и псевдонимы. `catalog-source.ts` отвечает только за файловое/HTTP(S)-чтение; `catalog-validation.ts` проверяет формат полученного документа. `imports.ts` читает каждый источник один раз на вызов, выбирает исходный namespace и адаптирует цели для потребителя. Эти операции отделены от чистого разрешения ссылок и не исполняются в Lua-фильтре.

`application/workflow.ts` получает импортированные цели через порт и сохраняет их в `BuildState`; `publish.ts` не выполняет сетевых запросов. Снимок действует на одну сборку. Загрузка источников не является менеджером зависимостей: постоянное кеширование, lock и Git API не входят в этот контракт.

`domain/exports.ts` выбирает публичное подмножество собственных целей. Полный локальный набор остаётся доступен `linkPages`; импортированные цели не входят в экспорт. Явное разнесение этих наборов предотвращает неявный транзитивный реэкспорт.

Заголовки получают дополнительное текстовое `title` через публичный AST и метаданные проб. `linker.ts` выбирает представление, а `browser/external.css` задаёт минимальный визуальный стиль. Текущая схема описывает публикацию; `sourceTitle` и `defaultStyle` существуют только у импортированных целей в памяти потребителя.

Общий составной проект может передать явные локальные `source` и адреса предпросмотра через конфигурацию. Расширение не ищет соседние репозитории, не запускает Git и не требует submodule. Самостоятельный курс использует тот же импорт с HTTP(S)-источником.
